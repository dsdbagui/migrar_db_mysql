## Motivação (evidência)

Root cause confirmada: o driver `mysql2` usa `UTF8MB4_UNICODE_CI` como charset padrão quando nenhum `charset`/`charsetNumber` é passado a `mysql.createConnection()` (`node_modules/mysql2/lib/connection_config.js:174-176`). `src/core/connectionManager.ts` não passava nenhum dos dois, então toda conexão (origem e destino) ficava nesse default — divergente da collation `utf8mb4_0900_ai_ci` que o resto da aplicação já assume como padrão do destino.

## Escopo explicitamente fora deste adendo

- Não altera nada sobre a conexão de ORIGEM — permanece sem charset explícito, para não quebrar contra um MySQL 5.x que não reconhece `utf8mb4_0900_ai_ci` (charset id 255, introduzido no MySQL 8.0.1).
- Não substitui nem altera o script standalone `fix_collation_stamp.py` (`_reversa_sdd/correcao-de-collation/`) — este adendo ataca a causa na aplicação web; o script legado continua existindo como ferramenta de correção pós-fato para bancos já migrados antes desta correção.
