## Problema 1 — Collation da conexão não acompanha o destino

- **Esperado (segundo o usuário):** antes de cada `CREATE` (tabela ou rotina), a conexão deve rodar
  `SET NAMES utf8mb4 COLLATE utf8mb4_0900_ai_ci`, alinhando com o collation padrão já usado em todo
  o resto da aplicação (`CREATE DATABASE ... COLLATE utf8mb4_0900_ai_ci` em `connectionManager.ts:102`,
  e todas as migrations do App DB em `src/core/db/migrations/`).
- **Observado:** nenhuma chamada de `SET NAMES` existe no código (`grep -rn "SET NAMES" src/` não
  retorna nada). `mysql.createConnection` em `connectionManager.ts:49-57` não passa `charset` nem
  executa `SET NAMES` — a conexão fica no default do driver/servidor, que o usuário identifica como
  `utf8mb4_unicode_ci`.
- **Código investigado nesta anotação (Suspected Area, não root cause confirmada):**
  - `src/core/connectionManager.ts` (`connect`, linha 43-79) — cria a conexão, sem charset/collation explícito.
  - `src/features/tables/apply.ts` (`applyTable`, linha 22-26) — roda `USE` + DDL, sem `SET NAMES` antes.
  - `src/features/routines/apply.ts` (`applyRoutine`, linha 13-21) — mesmo padrão, sem `SET NAMES` antes.
- **Spec:** nenhuma seção de `_reversa_sdd/migracao-de-tabelas/requirements.md` ou
  `_reversa_sdd/migracao-de-rotinas/requirements.md` menciona collation/charset da conexão
  (`grep -i "collation\|charset\|SET NAMES"` não retorna nada em nenhum dos dois). Comportamento
  nunca foi especificado — `spec-gap`.
- **Nota:** `_reversa_sdd/correcao-de-collation/requirements.md` existe, mas descreve um script
  standalone diferente (`fix_collation_stamp.py`, recarimba `DATABASE_COLLATION` de rotinas já
  criadas via DROP+CREATE) — não é o mesmo mecanismo nem resolve este defeito (que é sobre a
  collation da CONEXÃO no momento do CREATE, na aplicação web atual).

## Problema 2 — `sql_mode` das procedures mantém `IGNORE_SPACE`

- **Esperado (segundo o usuário):** `IGNORE_SPACE` deve ser removido do `sql_mode` das
  procedures/functions migradas, junto com o que já é removido hoje.
- **Observado:** `cleanSqlMode` em `src/features/routines/transform.ts:54-67` só remove
  `NO_AUTO_CREATE_USER` do `sql_mode` (via regex `/NO_AUTO_CREATE_USER/i`); `IGNORE_SPACE` não é
  tocado. Isso é consistente com o comportamento documentado em `CLAUDE.md`
  ("clean_sql_mode — removes NO_AUTO_CREATE_USER from sql_mode") — ou seja, não é regressão de uma
  spec existente, é uma regra nova sendo pedida agora.
- **Spec:** `_reversa_sdd/migracao-de-rotinas/requirements.md#RF-04` ("Aplicar as 8 transformações
  de compatibilidade da lista TRANSFORMATIONS, em ordem") cobre `cleanSqlMode` como uma das 8, mas
  não especifica o tratamento de `IGNORE_SPACE` — `spec-gap` quanto a este token específico.
